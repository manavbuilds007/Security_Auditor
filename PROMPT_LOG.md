## 2. Plan and approval

## 3. Implementation decisions

- **Engine is pure TypeScript** (no DOM) so it is unit-testable in Node.
- **Overlap resolution:** precedence first (CARD > AADHAAR > PAN > EMAIL > IPV6 > IPV4 > PHONE), then
  length, then position. Numeric patterns use lookarounds that refuse to match next to `@`, `.`, word
  characters, or adjacent digit groups, so digits are never carved out of emails or longer numbers.
- **Rejections:** non-Luhn 13–19 digit candidates (and Verhoeff failures when enabled) are recorded, shown
  with a dashed amber underline, counted, and left unchanged. Rejections overlapped by an accepted match are dropped.
- **IPv6:** a loose candidate regex followed by structural validation, so timestamps (`10:42:13`) and
  `std::vector` are not matched.
- **Pseudonyms:** fresh `Map` per run, keyed by normalized value (lower-cased email, digits-only
  card/Aadhaar, national number for phones, expanded IPv6). IPv4 and IPv6 share the `IP_` counter.
- **Category filters:** disabled categories still claim their span (so they are not re-detected as something
  else) and are counted, but are not replaced.
- **CSV:** deviation from the plan: no cell-level tokenizer is needed. Patterns cannot cross delimiters or
  line breaks and replacements contain none, so structure is preserved by construction.
  `src/utils/csv.ts` only detects the delimiter, describes rows/columns, and verifies the structure
  skeleton is unchanged. Line endings: textarea normalizes to LF, so the original ending is restored on edit.
- **Privacy:** CSP `connect-src 'none'` in `index.html` and `vercel.json`; no external fonts or scripts.
- Synthetic sample data only (public test card numbers, made-up identifiers).

## 4. UX polish pass

Request: clearer first-run experience, clearer control wording/tooltips, obvious export, and a "How it works"
section.

- **Empty states:** a shared `EmptyState` component. The input panel shows guidance plus *Try the sample
  log / CSV* buttons over the textarea (the overlay passes clicks through to the textarea). The Source pane
  repeats the sample buttons; the Sanitized pane explains what will appear. Panes return to normal as soon as
  there is text.
- **Controls:** numbered steps (1 add text, 2 choose how to redact, 3 copy/download). Tooltips explain Full,
  Partial, Pseudonymize ("stable token, restarts every run, nothing saved"), "Label what was removed" (typed
  tags, Full mask only) and the Aadhaar Verhoeff check (off by default so typos are still redacted). A live
  one-line summary under the controls describes the active mode.
- **Export:** moved into its own card with larger Copy and Download buttons, a status line, and a visible
  message if the clipboard is blocked.
- **How it works:** supported-formats table, Luhn false-positive explanation (~9 in 10 random 16-digit
  numbers fail Luhn; a rare Luhn-valid ID is still redacted, the safe direction), precedence order, and a
  three-mode example. The example outputs are generated by `sanitize()` at render time and asserted in
  `piiEngine.test.ts`, so the text cannot drift from behaviour.

## 5. Dark mode and motion

Request: add dark mode and make the site much more animated, with its use cases.

- **Dark mode:** a `.dark` class on `<html>` remaps Tailwind's color variables (`src/dark-theme.css`, generated
  from `tailwindcss/theme.css`: slate re-tuned by hand so panels, hovers and borders stay distinct; accent
  scales inverted). Every existing `bg-/text-/border-` class flips with no per-component `dark:` variants.
  `public/theme-init.js` is loaded synchronously from `<head>` (external, so the CSP `script-src 'self'` still
  holds) to apply the saved/system theme before paint. A brief `theme-fade` class cross-fades the switch.
- **Motion:** CSS keyframes in `index.css` (fade-up, mark-in, float, pop) and a `press` utility; small
  components `Reveal` (IntersectionObserver scroll-reveal), `AnimatedNumber` (count-up) and a sliding pill in
  `ControlsBar`. Output highlights replay a staggered glow when mode/options change (keyed by settings so the
  pane's scroll position is kept). Highlight animation avoids `transform` because `<mark>` is inline.
- **Use cases:** `UseCases` replaces the old banner: four cards plus `RedactionDemo`, an auto-playing tabbed
  before/after built from the real engine (clicking a tab pauses it).
- **Accessibility:** `prefers-reduced-motion` collapses all animation/transition durations and stops the demo
  auto-play. No animation library or network request was added.

## 6. Globe entry intro

Request: a dismissible, strictly client-side revolving-globe entry experience with regional leak scenarios,
a value-proposition overlay, Skip/Esc, session persistence and a header "Replay Intro".

- **Rendering:** `src/utils/globe.ts` holds the pure maths (orthographic projection, shortest-angle easing,
  point-in-polygon, land-dot sampling) so it is unit-tested in Node (`globe.test.ts`). `GlobeIntro.tsx` draws
  it on a 2D canvas: atmosphere glow, shaded sphere, graticule that breaks behind the limb, ~1k land dots
  that fade toward the edge, and pulsing pins. No WebGL, three.js, tiles or fetched data; bundle grew ~5 kB gzip.
- **Land data:** eleven coarse continent polygons written by hand (recognisable as dots, not cartography).
  A test asserts known land/ocean points and that all six hotspot cities fall on land.
- **Scenarios:** India (Bengaluru/Mumbai), North America (San Francisco/New York), Europe (Frankfurt/London),
  each with the leak and the outcome from the brief. The camera eases to each region (taking the short way
  round) with a slow sway so it always feels like it is revolving. They are labelled illustrative, not incidents.
- **Dismissal/persistence:** Skip, Launch and Esc all close it; `sessionStorage` (try/catch) remembered it for
  the session (later changed to `localStorage`, see section 8); Replay Intro reopens it and focus returns to the opener.
- **Accessibility:** `role="dialog"` + `aria-modal`, focus moved to the primary button and trapped, the
  workspace is `inert` while open, scenarios are real tabs (clicking one stops auto-advance), and under
  `prefers-reduced-motion` the globe is a static frame that redraws only on change.
- **Privacy check:** source scan found no network APIs or URLs. The production bundle had exactly one
  `fetch(`, from Vite's modulepreload polyfill (same-origin only, and no modulepreload links exist), so it was
  disabled (`build.modulePreload.polyfill = false`); the bundle now has none. CSP `connect-src 'none'` is unchanged.
  This is a static check; I did not capture a DevTools Network panel.
- The intro uses fixed hex colours rather than theme tokens so it looks the same in light and dark mode
  (dark mode remaps Tailwind's named colours).

## 7. Globe graphics + cursor reactivity

Request: enhance the globe graphics and make it react to the cursor.

- **Structure:** drawing moved to `components/globeRenderer.ts` (`drawGlobe(ctx, frame)` returns the pins'
  screen positions); `GlobeIntro.tsx` owns the animation loop and pointer handling. New pure maths in
  `utils/globe.ts`: great-circle `slerp`, `projectVec` (points floating above the surface), `isVisible`,
  `pointerToLight`, `nearestPin`, `clampLat`, pre-computed coastlines and graticule.
- **Graphics:** densified coastlines (soft wide pass + crisp thin pass), denser land dots, graticule, Fresnel-style
  atmosphere rim and outer halo, directional lighting with a terminator, seeded parallax starfield with
  twinkle, a tilted orbit ring whose back half is drawn behind the globe and front half in front, and leak
  arcs lifted 20% above the surface with travelling packets. The arc and pins start red and switch to green
  when the outcome text appears (`PROTECT_MS`), with a one-off ring burst.
- **Cursor:** light direction and a screen-blended spotlight follow the pointer; the camera leans up to
  ~6° toward it and the stars shift for parallax; dragging rotates (1 px = 1/R rad, latitude clamped) with
  inertia and an exponential return to the scenario framing; hovering a pin shows a tooltip and clicking it
  selects that scenario and stops auto-advance. Auto-advance also waits while dragging.
- **Touch:** `touch-action: pan-y` so vertical swipes still scroll the overlay while horizontal drags rotate.
- **Reduced motion:** no sway, pulses, inertia or auto-return; the loop redraws only when the user interacts.
- **Verification without a browser:** `globeRenderer.test.ts` runs the real renderer against a recording
  fake 2D context across 288 combinations (scenario, leak phase, camera angle incl. poles and the date line,
  cursor/drag states) and fails on any non-finite number passed to a canvas call, since NaN/Infinity makes a
  real canvas throw or drop the call. It also checks pin order/positions, red→green switching and tooltip
  rules. This does not replace looking at it: visual quality and feel were not seen.
- **Network:** re-scanned source and bundle: no `fetch`/XHR/WebSocket/beacon, no external URLs.

## 9. Copy accuracy and rendering fixes

Input: a second review found places where the interface said things the app does not do, plus rendering bugs.

- **Copy vs behaviour:** "drop in a file" had no handler, so drag-and-drop was built (window-level listeners that
  always cancel the browser's navigate-to-file default, load only while the workspace is active, accept `.txt` /
  `.csv` or text MIME types and show an alert for anything else). The globe outcome "Blocked locally before
  upload." claimed the app blocks uploads; it now says "Scrubbed in your browser before you paste it anywhere."
  "Dashed amber underline" was stale: the description and the rejected-mark class now live together
  (`REJECTED_MARK_*`) and a test fails if they diverge. A second test forbids block/prevent/intercept/stop wording
  in scenario copy.
- **Invisible section:** `Reveal` used an IntersectionObserver, which never fires for a block you jump past
  (End key, scrollbar drag), leaving it at opacity 0. It now checks on scroll/resize and reveals anything at or
  above the viewport (`shouldReveal`, tested).
- **Squashed icon:** the empty-state guide was absolutely positioned inside a fixed 240px box, so taller content
  squeezed the icon (32×10px). When empty, the guide is in normal flow, the box grows to fit, the textarea fills
  it behind, and icon/buttons are `shrink-0`.
- **Result in view:** step 2 was ~530px tall and pushed the result below the fold. The three switches are folded
  into "Advanced options" (with a "changed" badge when non-default), the layout is `max-w-7xl`, and at ≥1280px step
  2 is a sticky right column (`21rem`, scrolls internally if the viewport is short).
- **Pane drift:** the labels and redactions change line wrapping, so two independently scrolled panes could not stay
  aligned. The panes are now one grid of source|sanitized line pairs (`pairLines`, tested) in a single scroll
  container; no scroll syncing. Capped at 3,000 rendered lines to keep typing responsive.
- **Source pane colour-only:** type labels now show in both panes (one switch).
- **Empty state / phone summary:** the rejected-count line is hidden until there is text; summary notes stack in a
  single column below `sm`, each as one sentence.
- **Verification:** unit tests, type-check and build; no browser was available, so layout fixes were reasoned
  from the DOM/CSS rather than measured.

## 10. Regex edge cases

- **`ticket#9876543210`:** the Indian-mobile pattern's lookbehind now also excludes `#` (it already excluded word
  characters, `@`, `.` and `+`), so an identifier is not read as a phone number. `ticket 9876543210` and
  `ticket: 9876543210` are still detected. I did not add `-` to the lookbehind as the example suggested: that
  would also stop `ref-9876543210` but would change how numbers after a hyphen are handled elsewhere, which was
  not requested.
- **PAN:** the pattern is now `[A-Z]{3}[ABCFGHLJPT][A-Z]\d{4}[A-Z]`; the 4th letter is the holder type (P, C, H,
  F, A, T, B, L, J, G), so `ERROR1234X` no longer matches. Consequence: the old fixture `ABCDE1234F` (4th letter
  `D`) is not a valid PAN shape, so tests, sample data and help text now use `ABCPE1234F` / `FGHCJ5678K`.
- **Tests:** two regression tests (ticket-ID vs phone; every valid holder type accepted, a set of invalid ones
  rejected, `ERROR1234X` untouched). I confirmed both fail against the previous patterns and pass with the fix.
- **Not changed:** the same `#` prefix still lets `ticket#<12 digits>` be read as an Aadhaar number (no checksum
  by default) and card numbers are only protected by Luhn. Left alone because only the phone pattern was in scope.

## 11. Pre-publication security audit

Run before the first push to GitHub. Read-only checks first, then fixes.

- **Secrets:** pattern scan (cloud/GitHub/Slack/OpenAI/Anthropic/Google keys, private keys, JWTs, `key=`/`token=`
  assignments) over the working tree and every commit in history: nothing. No `.env`, key, cert, `.npmrc` or
  credential file was ever committed. `dist/` and `node_modules/` are ignored.
- **Personal data:** no absolute paths, usernames, hostnames or the owner's email in any tracked file or history.
  All sample emails are synthetic and now use RFC 2606 reserved domains (`example.com` / `example.org`); cards are
  public test numbers; IPs are private/documentation ranges; PANs and phones are fictional. Residual: the sample
  Aadhaar numbers are Verhoeff-valid by construction, so a tiny fraction of such numbers could be assigned to a real
  person; they are sequential patterns, but they cannot be proven unassigned.
- **Shipped bundle:** no source maps, no local paths or hostnames inside `dist/`.
- **Code:** no `dangerouslySetInnerHTML`/`innerHTML`/`eval`/`document.write`/`window.open`, no `fetch`/XHR/
  WebSocket/beacon/cookies/IndexedDB, no `console` output. The only persisted values are `theme` and the intro
  dismissal flag (`localStorage`); user text is never stored.
- **Supply chain:** lockfile is entirely `registry.npmjs.org` with integrity hashes; no install lifecycle scripts
  in `package.json`; 3 runtime dependencies.
- **Vulnerabilities:** `npm audit` reported 3 advisories (2 critical, 1 moderate), all in the dev-only test runner
  (Vitest 3.x via `tinypool` and `@vitest/mocker`); production dependencies had 0. Upgraded to Vitest 5.1.2: audit
  now reports 0 and all tests pass.
- **Hardening:** `.gitignore` now also covers `.env*`, key/cert files, `.npmrc`, `coverage` and `.vercel/` (which
  holds Vercel project/org IDs). `vercel.json` adds `Permissions-Policy` (camera, microphone, geolocation, payment,
  USB, serial, Bluetooth off) and `Cross-Origin-Opener-Policy: same-origin`.
- **Not changed / open:** (1) commit author is a machine-local identity (`...@<hostname>.local`) that would become
  public; fixing it needs the owner's choice of email. (2) CSP keeps `style-src 'unsafe-inline'`; React sets inline
  styles through the CSSOM, which strict CSP allows, so it can probably be removed, but that must be verified in a
  browser. (3) There is no LICENSE file, so the code is all-rights-reserved by default; that is the owner's choice.
